## 二、 当前全局规则（`rules/*.md` 模块化结构）

目前全局规则已重构为模块化独立 Markdown 文件，存储于 `rules/` 目录下，按职责解耦如下：

1.  **`git_rules.md` (Git 代码提交规范)**：
    *   每次修改代码或完成开发任务后，自动执行 Git 提交与推送命令（`git add`、`git commit` 以及 `git push`），提交信息必须使用中文。
    *   **前置审查**：在执行 Git 自动提交前，自动针对本次修改的文件开展代码清理审查，识别并清除所有无用导入（Unused Imports）和未引用局部变量。
2.  **`build_rules.md` (编译与打包规范)**：
    *   代码修改完成后，不需要自动运行打包构建脚本（如 `npm run build` 或 `vite build`）。只有当用户明确下达打包指示时才进行构建。
3.  **`performance_log_rules.md` (日常工作日志与绩效记录规范)**：
    *   每次协助用户完成具体的开发任务、修复 Bug、重构代码、优化性能、本地调试或解答技术方案后，自动将成果追加到 `/Users/jianjian/z4pro/ai月度绩效/ai月度绩效.md`。
    *   **触发限制**：仅当被修改/清理的代码文件位于 `/Users/jianjian/greatmap/workspace/` 路径下时，才触发日志写入。
    *   **归档机制**：历史月份日志按月物理归档至 `/Users/jianjian/z4pro/ai月度绩效/archive/`。
    *   **同步规则**：仅在本地追加更新，不需要进行 Git 提交或推送。
4.  **`CLAUDE.md` (AI 编码与协同行为准则 - 高效英文版)**：
    *   **Think Before Coding**：不猜测不臆断，不确定立即提问，并展示多种设计利弊。
    *   **Simplicity First**：只实现明确提出的需求，不为单次功能做过度设计。50 行解决的绝不写 200 行。
    *   **Surgical Changes**：只修改必要行，不顺手碰相邻代码及格式，风格完全匹配原项目。
    *   **Goal-Driven Execution**：任务细化为可验证的 goal，进行闭环对比验证。
5.  **`temp_script_rules.md` (临时脚本与辅助文件规范)**：
    *   辅助中转测试脚本优先存储于系统临时目录，若在工作区落地则在任务结束最后一步自动删除销毁，切勿污染工作区。
6.  **`typography_rules.md` (中文排版无空格与全英文标点规范)**：
    *   在生成所有文本时，中文与数字、中文与英文之间**严禁自动添加半角空格**。同时，所有标点符号必须统一使用**英文半角标点**。
7.  **`desktop_file_rules.md` (生成文件存放项目根目录gemini文件夹规范)**：
    *   凡是协助用户完成任务生成的各类交付文件成果（包括设计方案、SQL脚本、整理导出的 TXT、Word、Excel、JSON、PDF、代码压缩包、比对报表等各类数据文件），除项目工程源码直接修改提交外，一律在当前对应项目根目录下创建 `gemini` 目录（`<项目根目录>/gemini/`），并统一生成存放到该目录中，保持电脑桌面整洁并按项目归口管理。
8.  **`markdown_rules.md` (Markdown文档与表格排版规范)**:
    *   所有Markdown文档必须严格遵守表格列宽垂直对齐规范.生成或修改任何 `.md` 文件时,严格遵循JetBrains等IDE底层Java UTF-16字符等长检查机制(含Emoji占2个UTF-16代码单元的对齐补偿),单元格按最大宽度补齐填充空格,居中对齐单元格严格左右对称,竖线 `|` 上下严格对齐,分隔行长度精确匹配,彻底消除IDE中“表的格式不正确”(Incorrect table formatting)黄色波浪线警告.凡追加或更新数据行,必须同步重新计算列宽并整体重排.
9.  **`copy_format_rules.md` (可复制文本代码块封装规范)**:
    *   凡是在回答或报告中向用户提供需要复制、粘贴或录入到外部文档/系统（如周计划C/F列、周报、日报、工时明细、配置项、清单列表等）的文本内容时，必须一律统一使用纯文本代码块（```text）独立封装展示，严禁直接使用 Markdown 有序列表渲染（避免被解析为 `<ol><li>` 导致划词复制丢失序号），确保右上角一键无损复制且 `1. 2. 3. 4.` 等序号 100% 完整保留。
10. **全局配置变更自动同步** (`skill_sync_rules.md`)：
    *   每次当用户修改了全局规则或 Skills 后，助手**必须自动**将变更同步登记到本登记簿文档中，并自动执行 Git 提交与推送。

## 四、 维护与使用建议

1.  **全局规则（AGENTS.md）修改**：
    *   仅在需要新增所有项目都必须遵循的系统级行为（如提交信息格式、全局日志记录路径等）时，才直接修改 `AGENTS.md`。

2.  **技能（Skills）的添加与剔除**：
    *   如需添加新技能，直接在 `/Users/jianjian/.gemini/config/skills/` 下新建包含 `SKILL.md` 的文件夹即可，无需手动在平台注册。
    *   如需删除或禁用某技能，将其文件夹从上述路径移出或删除即可。
